# 悪用への備えの点検（Mimita 0.9.2 の見直しを Fuseo に当てはめる）

**記録日時**: 2026-11-15 14:30 (JST)　**状態**: 調査と報告のみ。修正・公開・規約の変更は竹屋さんの判断待ち
**対象**: Mac 0.3.0（配布中・/Applications の公開版のバイナリも確認）、iOS 1.2.6（App Store。アプリ層は非公開リポジトリ外）、Windows 0.3.2（配布停止中・署名後に 0.3.3 で再公開予定）
**参考**: ~/polaris_meeting_agent/docs/TRUST_TRANSPARENCY.md の「0.9.2」、~/polaris_meeting_agent/docs/legal/TERMS_DRAFT.md
**範囲外**: Tameo（~/polaris_tameo）は別プロジェクトのため、このセッションでは調べていない

## 結論

- 外から操作できる入口（ネットワークの待ち受け、URL での起動、ほかのアプリからの命令）は、3 つの版とも実質的に無い
- ただし Mimita と同じ種類の問題が 2 つある
  - **Mac**: UI テスト用の起動の引数（`--uitest`、`--uitest-fixture <パス>` など）が配布版でも効く
  - **Windows**: E2E 用の環境変数 `FUSEO_DATA_DIR`（データの場所の差し替え）が配布版でも効く
- どちらも、Fuseo は通信しないので、借りた権限で書類を外に出す経路にはならない。重要度は **低〜中**
- 文書の側では、**プライバシーポリシーに実装と違う記述がある**（Mac ではアプリを消しても作業中の書類が残る）。こちらを先に直すことを勧める
- 利用条件（利用規約）は 3 つの版とも存在しない。あるのは MIT ライセンスとプライバシーポリシーだけ

### 試験用の操作の口

- **Mac【問題 A】**: `FuseoApp.isRunningTests` は、環境変数 `XCTestConfigurationFilePath` か引数 `--uitest` で真になる。配布版でも同じ
  - `--uitest-fixture <パス>`: 指定したファイル・フォルダを起動と同時に読み込む（PDF のページは一時フォルダに画像として書き出す）
  - 作業中の書類の保存先が `$TMPDIR/fuseo-uitest-library` に変わる
  - その起動では Sparkle（アップデートの確認）が止まる
  - `--uitest-open-settings`: 設定の画面だけを出す
  - 配布版（/Applications/Fuseo.app 0.3.0）のバイナリに `--uitest-fixture`・`--uitest-open-settings`・`fuseo-uitest-library`・`XCTestConfigurationFilePath` の文字列が残っている（`strings` で確認済み）
- **iOS**: 同じ引数（`--uitest`）と環境変数（`UITEST_FIXTURE_B64`・`UITEST_FIXTURE_PDF_B64`）がある。ただし iOS では、ほかのアプリが引数や環境変数を付けて Fuseo を起動する方法が無い（Xcode・devicectl などの開発用の道具だけ）。実質的な影響は無い（OS の仕組みによる推測）
- **Windows【問題 B】**: `AppDataLocation` が環境変数 `FUSEO_DATA_DIR`（絶対パス）で、設定と作業中の書類の場所を差し替える。Release のビルドでも有効（`#if` が無い。コードで確認済み）。配布物の exe は 1 ファイルに圧縮されているため、文字列の検索では見つからなかった（バイナリでの確認は未完）

## 3. 権限を借りられる経路

- **Mac**: Fuseo はカメラ・マイク・画面収録の許可を使わない。借りられる可能性があるのは、利用者が過去に Fuseo へ与えた「書類」「デスクトップ」「ダウンロード」フォルダへのアクセスの許可（TCC）だけ
  - 問題 A の引数を使うと、ほかのプログラムが Fuseo にそれらのフォルダのファイルを読ませ、ページの画像を保護の無い一時フォルダ（`$TMPDIR`）に書かせられる。つまり、フォルダの許可を持たないプログラムが、Fuseo の許可を借りて書類の画像を手に入れる経路になりうる
  - ただし、利用者がファイルを選んで・ドラッグして開いた場合は、その都度の許可で済むため、Fuseo がフォルダ全体への恒常的な許可を持っているとは限らない（推測。実機の TCC の状態は未確認）
  - Fuseo は通信しないので、Fuseo 自身が書類を外へ送ることはない
- **iOS**: カメラの許可はあるが、ほかのアプリが Fuseo を操作する口が無い。実質的な経路は無い
- **Windows**: アプリごとの許可の仕組みが無い（同じ利用者のプログラムは同じ権限で動く）。借りる意味のある権限は無い。UI オートメーションでほかのプログラムが画面を操作することは OS の仕組みとして可能（Fuseo 側では防げない）
- **共通（保存されたデータ）**: 作業中の書類（黒塗り前の画像を含む）は、Mac は `~/Library/Application Support/Fuseo`、Windows は `%LOCALAPPDATA%\Fuseo\Library` にあり、同じ利用者のほかのプログラムから読める。macOS のサンドボックス化していないアプリのデータは TCC で保護されない（推測。OS の仕様）。iOS はアプリのコンテナの中で、ほかのアプリからは読めない

## 4. 認証の情報の保管

- API キー、アカウント、トークンの類は、3 つの版とも持たない（確認済み。コードに保管の処理が無い）
- 配布物に入っている鍵は、Sparkle の公開鍵（SUPublicEDKey）だけ。公開されて問題ない値

## 5. 外部のサービスの経由地にされないか

- 外部のサービスにつなぐ機能が無い。通信は Mac 版の Sparkle（appcast は fuseo.ati-mirai.co.jp、DMG は GitHub）だけ
- iOS・Windows は通信のコードを持たない（`URLSession`・`HttpClient` などの使用なし。確認済み）
- 中継に使える部分は無い

## 6. 利用条件・プライバシーの文書

### 6-1. 利用条件

- **Fuseo には利用条件の文書が無い**。公開物にあるのは次だけ
  - LICENSE（MIT。Mac 版・処理エンジン・Windows 版のソース）
  - PRIVACY.md（3 つの版の共通）
  - SECURITY.md
  - Windows の README.txt（MIT と同梱部品のライセンスの案内）
  - iOS は App Store の標準の使用許諾（Apple の標準 EULA）が適用されている見込み（App Store Connect は未確認）
- Mimita の改訂後の条項と比べた抜け

| 条項 | Fuseo |

| PC の環境と認証の情報 | 無い（認証の情報は持たないので、PC の環境と保存データの管理だけでよい） |
| 責任の範囲 | MIT の「現状のまま・いかなる場合も責任を負わない」だけ |
| 利用者による賠償 | 無い |
| 権利の帰属 | MIT の著作権表示だけ。書き出したファイルが利用者のものであることは書いていない |
| 更新・利用の停止・終了 | 無い |
| 反社会的勢力の排除 | 無い |
| 分離可能性 | 無い |
| 準拠法・裁判所 | 無い |
